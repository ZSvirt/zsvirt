= 安全修复及旧版本升级说明

关联工单：http://jira.zstack.io/browse/ZSV-13183[ZSV-13183]。

当前代码范围包含 GLock 参数绑定、账号密码双格式支持及全新安装配套。迁移网关共用凭据尚未修改，不能将邮件中的七项全部关闭。

== 本轮方案与安装行为

* GLock 获取和释放锁使用参数绑定，不改表结构、正常锁名、超时及持久化格式。已有回归包含新旧 SQL 双向互斥；异常名称按字面处理，不承诺与旧节点错误的 SQL 转义结果一致。
* 标准 CLI 已发送 SHA-512 验证值，不能笼统称为明文存储。服务端新增 PBKDF2-HMAC-SHA512 保护这个输入，客户端密码与输入协议保持不变。
* identity.enableSaltedPassword 的配置默认值仍为 false，避免 GlobalConfig 默认值刷新在升级时自动启用新格式。
* 新安装脚本设置 identity.saltedPasswordOnFreshInstall=true；管理端还要求 AccountVO 和 ManagementNodeVO 都为空，才启用持久化的新写入开关。新建 admin 使用同一编码器，用户仍使用原始初始密码登录。
* 升级脚本设置引导标记为 false，不修改持久化的新写入开关，不转换任何旧记录。已启用新格式的安装也不会因升级而被强制关闭。
* 新节点接入已有数据库时，即使本地带有新安装标记，已有账号或管理节点会阻止自动启用。已有 admin 密码和修改时间不重写。
* 直接部署 WAR、绕过本安装脚本的安装默认使用兼容模式，需要在全部管理节点支持新格式后按下文启用。

安装配套位于 zsvirt-utility 的 installation/install.sh，必须与管理端补丁同批交付。正式构建的 zstackbuild/build.zsv.xml 从该路径打包安装脚本；只合入管理端 MR 不会让新装自动启用。制品验收需检查生成的安装脚本在新装和升级路径都调用 configure_salted_password_bootstrap。

== 网关凭据方案（待镜像源码配套）

当前共用密码不仅用于平台到管理网关的 SSH/sudo，还用于管理网关向其他网关分发 VDDK。仅旋转管理网关密码会使其他网关认证失败，不能作为完整修复。

完整方案需在网关镜像首次启动时注入独立随机凭据或密钥，以加密的资源级凭据记录按网关读取；同时区分分发源和目标的认证材料。新镜像不应继续开放共用默认凭据。已有网关继续使用原配置，轮换是独立维护操作，需验证新凭据成功、持久化及失败恢复；不能只变更 GlobalConfig 默认值。

本机仅找到 ZMigrate UI 安装脚本，没有找到网关镜像内的账号初始化和 SSH 配置制作源码。此项仍未修复，不自动改变旧网关密码。

== 默认升级行为

* 不改数据库表结构，不重置账号密码，不自动转换历史密码。
* 新增 identity.enableSaltedPassword，默认 false。此时创建和修改密码仍沿用原存储格式。
* 新版本始终能读取旧记录和本补丁的新记录。旧记录在登录、二次认证和敏感操作校验时保留数据库原有的比较规则；旧密码修改及历史密码比较保留原有字符串比较方式。
* CLI/UI 的原有 SHA-512 输入协议保持不变。新格式对这个输入做服务器端带盐慢哈希，而不是要求客户端发送数据库里的新值。
* 不自动切换迁移网关密码、Ceph 通信协议或已有序列化任务格式。

默认 false 是滚动升级期间的兼容措施。仅安装新代码，不启用新写入及转换旧记录，不能算消除账号存储风险。

== 启用账号存储保护

新格式使用 PBKDF2-HMAC-SHA512、220000 次迭代、16 字节随机盐和 256 位输出。参数依据 https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html[OWASP Password Storage Cheat Sheet]。带版本标识的存储值为 121 个字符，兼容现有 varchar(255) 字段。

. 完成全部管理节点升级，确认每个节点包含 AccountPassword 和所有配套校验改动，完成登录、改密、二次认证和历史密码策略的集成回归。
. 备份数据库，保护备份中的旧验证值，并明确回退版本。不要在仍有旧管理节点服务时开启新写入。
. 在已登录的 zstack-cli 中执行：

[source,text]
----
UpdateGlobalConfig category=identity name=enableSaltedPassword value=true
----

. 验证新账号和改密后的账号使用新格式，原密码仍能通过原 CLI/UI 登录。
. 在维护窗口停止所有管理节点、保留数据库运行，避免直接数据转换与 ORM 缓存、后台改密任务互相覆盖。使用下述工具转换现有账号及历史密码，然后重新启动管理节点。
. 再次执行 dry-run，确认有效旧记录已处理，并验证已有 admin、普通账号、二次认证和密码历史策略。

== 旧数据转换工具

AccountPasswordMigration.java 是独立维护工具，不会被管理服务自动执行。不需要知道原始密码，使用现有服务端验证值作为哈希输入。默认 dry-run 不写数据。

在包含本补丁的新安装目录编译，以下命令需按实际工具路径和本地数据库端口调整。数据库用户名和密码由终端交互读取，不放进命令行。

[source,bash]
----
LIB=/usr/local/zstack/apache-tomcat/webapps/zstack/WEB-INF/lib
WORK=$(mktemp -d)
javac -cp "$LIB/*" -d "$WORK" /path/to/AccountPasswordMigration.java
export ZSTACK_DB_URL='jdbc:mysql://127.0.0.1:3306/zstack?useSSL=false'
java -cp "$WORK:$LIB/*" AccountPasswordMigration
# 完成节点升级、数据库备份及维护窗口准备后才执行：
java -cp "$WORK:$LIB/*" AccountPasswordMigration --apply
----

apply 同时要求数据库开关为 true，并要求操作者确认升级和备份已经完成。这个确认不能自动证明所有节点均已升级，操作者仍需逐一核实。

工具处理 AccountVO.password 和 HistoricalPasswordVO.password。已有新格式和 null 值不转换；条件更新避免覆盖转换期间发生的改密。保留账号 lastOpDate 和历史 createDate，不重置密码年龄。输出仅包含计数，不输出密码或哈希。

每条更新独立提交；中途失败可能留下新旧混合数据，新代码可读取这种状态。排除故障后重复执行；已转换的记录不重复哈希。需要检查 changed-concurrently 计数，并在业务静止后重试。

== 回退边界

新版本读取旧格式属于前向升级兼容，不代表旧二进制能读取新格式。一旦启用新写入或转换出新记录，关闭开关只停止新写入，不还原已经生成的哈希。

此后回退必须使用支持新格式的版本，或按已验证的数据库备份恢复方案处理；恢复备份还会恢复相应时点的密码及其他业务数据。不能承诺无需处理数据即可降级任意旧版本。

旧格式的数据库比较可能不区分大小写，而新格式对输入精确校验。标准 CLI/UI 生成的 SHA-512 输入不变；直接调用 API、依赖旧排序规则接受不同大小写或特殊输入的客户端，需要在启用前单独验证。

== 邮件其余项目的状态

* 迁移网关共用默认凭据：风险确认，未修复。直接改默认值会触发 GlobalConfig 升级刷新，可能改变旧环境正在使用的密码而网关端密码不变，导致 SSH/sudo/升级失效。需要镜像初始化和存量网关轮换配套实现与验证。
* Ceph HTTP 传递 SSH 凭据：风险确认，未修复。Base64 和 NoLogging 不能提供传输加密。需要管理端、agent、证书验证或安全隧道能力配套验证；只改 URL 会破坏旧 agent 通信。
* Java 反序列化：存在无过滤读取，尚未确认外部输入可达及可用利用链。调用方包含持久化任务、工作流和 KeyValue。严格白名单或格式替换需要合法旧对象样本及旧任务恢复回归，未在本补丁修改。
* ShellUtils：bash -c 本身是工具能力，报告未给出不可信输入到危险命令的具体路径；未宣称不存在风险，也未全局禁用该工具。
* 主机路径校验：现有代码已有绝对路径、遍历片段和字符限制，挂载点已有专用验证。尚未确认可越权的具体路径；不能在管理节点上解析远端主机路径后宣称完成修复。
