= 安全修复及旧版本升级说明

关联工单：http://jira.zstack.io/browse/ZSV-13183[ZSV-13183]。

== 账号密码存储行为

本次首次引入平台账号密码的带盐存储格式。新建账号和正常修改密码始终使用新格式，不需要配置开关、安装标记或批量迁移工具。

* 全新安装创建的 admin 使用新格式，用户仍使用原始初始密码登录。
* 存量账号密码不自动转换，升级、管理节点初始化和登录均不会重写已有密码或其时间戳。
* 已有 admin 和普通平台账号通过原有 UI/CLI 修改为不同于当前密码的新密码后，新密码按新格式保存；之后使用新密码登录。
* 登录按数据库中保存的格式选择校验方式。旧格式保留原有数据库比较规则；新格式通过前缀识别并进行 PBKDF2 校验，失败时不退回旧格式比较。
* 已有历史密码记录保持原样。后续改密保存的历史记录使用新格式，已编码记录不会重复哈希；新旧格式均参与密码历史校验。
* 设置与当前相同的密码不能作为格式转换操作，且可能被密码历史策略拒绝。

标准 CLI/UI 发送的 SHA-512 验证值及输入协议不变。服务端使用 PBKDF2-HMAC-SHA512、220000 次迭代、16 字节随机盐和 256 位输出保护该验证值；带版本前缀的存储值为 121 个字符，兼容现有 varchar(255) 字段。

保护范围是 ZStack 平台自身的账号密码，不包含宿主机、虚拟机操作系统、迁移网关或 LDAP/SSO 外部认证系统的密码。未改密账号和原有历史密码记录仍保留旧格式，不能将本方案描述为已完成全部存量密码加固。

== 升级与验收

. 升级前备份数据库并明确回退版本。
. 升级期间暂停账号创建和改密，待共享同一数据库的所有管理节点均完成升级后恢复业务；旧版本节点无法验证新格式密码。
. 验证已有账号可以用原密码登录，登录不会改写其存储值。
. 验证新建账号使用新格式且能正常登录。
. 让已有账号通过正常改密流程设置新密码，验证新密码可登录、旧密码失效，并检查密码历史策略与二次认证。

新密码保护不依赖安装脚本，直接部署 WAR 也使用同样的存储规则。无需为密码格式转换额外停服，也没有独立的数据转换步骤。

旧格式的数据库比较可能不区分大小写，而新格式对输入精确校验。标准 CLI/UI 输入不变；依赖旧排序规则接受不同大小写或特殊输入的 API 客户端需要单独验证。

== 回退边界

新版本兼容旧密码，不代表旧版本兼容新密码。一旦新建账号或改密产生新格式记录，不能直接回退到只支持旧格式的版本。回退需使用支持新格式的版本，或按已验证的数据库备份恢复方案处理；恢复备份也会恢复相应时点的密码及其他业务数据。

== 回归范围

* TestAccountPassword 覆盖旧格式校验、新写入随机盐、null 输入、非法格式、拒绝哈希回放及新旧历史密码比较。
* AccountSaltedPasswordCase 覆盖存量账号登录不重写、存量账号正常改密后使用新格式、新账号登录和改密、二次认证及新旧密码历史校验。
* AccountPasswordFreshInstallTest/Case 覆盖空库初始化 admin 的新格式存储、初始密码登录和重复初始化不重写账号。

这些用例不能替代整包安装升级、多管理节点和实际客户端的验收；完整 Spring/AspectJ 集成用例及整包升级尚需执行。

== 邮件其余项目的状态

* 迁移网关共用默认凭据：风险确认，未修复。直接改默认值会触发 GlobalConfig 升级刷新，可能改变旧环境正在使用的密码而网关端密码不变，导致 SSH/sudo/升级失效。需要镜像初始化和存量网关轮换配套实现与验证。
* Ceph HTTP 传递 SSH 凭据：风险确认，未修复。Base64 和 NoLogging 不能提供传输加密。需要管理端、agent、证书验证或安全隧道能力配套验证；只改 URL 会破坏旧 agent 通信。
* Java 反序列化：存在无过滤读取，尚未确认外部输入可达及可用利用链。调用方包含持久化任务、工作流和 KeyValue。严格白名单或格式替换需要合法旧对象样本及旧任务恢复回归，未在本补丁修改。
* ShellUtils：bash -c 本身是工具能力，报告未给出不可信输入到危险命令的具体路径；未宣称不存在风险，也未全局禁用该工具。
* 主机路径校验：现有代码已有绝对路径、遍历片段和字符限制，挂载点已有专用验证。尚未确认可越权的具体路径；不能在管理节点上解析远端主机路径后宣称完成修复。
